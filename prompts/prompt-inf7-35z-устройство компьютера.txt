# РОЛЬ
Ты — опытный учитель информатики, методист и сильный фронтенд-разработчик. Ты создаёшь интерактивные тренажёры, которые работают офлайн на школьных ноутбуках, интерактивной доске и телефонах и публикуются как страницы простого сайта на GitHub Pages.

# ЗАДАЧА
Создай интерактивный тренажёр: «Информатика, 7 класс. Тема: №1 · Устройство компьютера».
Тренажёр содержит 35 уникальных заданий; кнопка «Новый вариант» и каждый запуск дают новый вариант: другой порядок, другая выборка из источников (если их пул больше 35) и свежая генерация собственных заданий.

# СОДЕРЖАНИЕ
- Ориентир: ВПР по информатике, 7 класс, каталог «Решу ВПР» (inf7-vpr.sdamgia.ru).
- Стиль заданий: формулировки в стиле ВПР: краткое однозначное условие, привычная форма ответа.
- Форма ответа: определи по теме и типу задания; приведи к привычной для этого типа форме (число, слово, последовательность); сравнение без учёта регистра и лишних пробелов.
- Сложность: от простых к сложным: первая треть — базовые, середина — средние, финал — высокие.
- Порядок заданий фиксированный: от первого к последнему.
Источники заданий:
  1) https://inf7-vpr.sdamgia.ru/test?theme=1 — режим «максимально точно по задаче». Примечание: есть ответы, по страница подгружается лениво.
  2) https://inf7-vpr.sdamgia.ru/test?theme=1&print=true — режим «максимально точно по задаче». Примечание: без ответов, но сразу все задачи..
Правила работы с источниками:
  • «Максимально точно по задаче»: воспроизводи задания со страницы без изменений — те же условия, числа, варианты ответов и эталоны; рандомизацию к ним не применяй.
  • «Только как пример задачи»: берём тип, структуру и стиль оформления задания, а условия и числа генерируй свои.
  • Если заданий по ссылкам МЕНЬШЕ, чем 35: недостающие сгенерируй сам — максимально похожие на источники по типу, формулировкам, структуре и уровню сложности.
  • Если заданий по ссылкам БОЛЬШЕ, чем 35: возьми только часть — ровно 35, равномерно по типам и сложности (или по примечаниям к ссылкам).
  • Если содержимое ссылок тебе недоступно: генерируй типовые задания того же вида и уровня, а в комментарии в начале файла честно укажи, что источники не открывались и задания созданы по мотивам.
- «Точные» задания храни как есть с проверенными эталонами; собственные и «примерные» генерируй процедурно (шаблоны + диапазоны параметров), эталоны вычисляй алгоритмически. Банк собственных заданий собирай из 3–6 шаблонов с формулой эталона.
- Параметры собственных и «примерных» заданий рандомизируются так, чтобы ответы были корректными и целыми там, где это уместно; задания внутри варианта не повторяются.
- Реши и перепроверь эталон каждого задания до выдачи кода: ошибки в эталонных ответах недопустимы.

# ПОМОЩЬ УЧЕНИКУ
- Проверка — мгновенная, по кнопке «Проверить» и клавише Enter; результат показывается явно: верно / неверно.
- Задания показываются по одному: счётчик «k из 35», прогресс-бар, кнопки «Дальше» и «Назад».
- Подсказки: включены — кнопка «Подсказка» даёт наводящую мысль, не раскрывая ответ (не более двух на задание).
- Пошаговый разбор после ответа: включён — после ответа показывается решение по шагам с вычислениями.
- Два режима: «Тренировка» и «Экзамен»; по умолчанию — «Экзамен» — подсказки и разбор скрыты до итогового экрана.
- Таймер: отключён.
- Итоговый экран: «X из 35», затраченное время, список ошибок с разбором, кнопка «Новый вариант».
- Сохранение прогресса: включено через localStorage (работает офлайн), с кнопкой «Сбросить прогресс».

# ВЗАИМОДЕЙСТВИЕ — РЕШАЕМ НАЖАТИЕМ
- Тренажёр максимально приспособлен для нажатий: мышь, тачскрин, палец или рука на интерактивной доске, стилус — всё работает одинаково.
- Основной способ ответа — нажатие: варианты ответа оформлены как крупные кнопки-карточки; после нажатия сразу виден результат (подсветка верно/неверно).
- Где это подходит типу задания, добавь перетаскивание: сопоставление пар, порядок шагов алгоритма, расстановка по группам, сборка последовательности. Реализуй на Pointer Events (мышь + палец + перо), с подсветкой цели; бросок мимо цели возвращает элемент на место.
- У каждого перетаскивания есть альтернатива без drag: «нажать источник → нажать цель» — так задание решаемо и без точных движений.
- Ответы-последовательности набираются нажатием по плиткам с буквами/цифрами (кнопки «Стереть» и «Очистить»); числовые — крупной экранной цифровой клавиатурой (0–9, ⌫) как альтернативой системной.
- Свободный ввод с клавиатуры оставь запасным способом (для ноутбука), но не основным.
- Кликабельные зоны не меньше 48×48px, зазоры между ними не меньше 8px; никаких действий, зависящих от hover, двойного клика или правой кнопки мыши; перетаскивание не должно конфликтовать с прокруткой страницы (touch-action на draggable-элементах).

# ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ — ЖЁСТКИЕ
1. Ровно один самодостаточный файл trainer.html: разметка, стили и скрипты внутри.
2. Полностью офлайн: без CDN, внешних шрифтов, картинок из сети, fetch и любых API.
3. Чистый JavaScript без фреймворков и сборки; никакого Node.js, npm, импортов из сети.
4. Файл открывается двойным кликом (протокол file://) в Chrome, Edge и Firefox и работает как страница GitHub Pages без изменений.
5. Кодировка UTF-8 (<meta charset="utf-8">) и <meta name="viewport" content="width=device-width, initial-scale=1">; весь интерфейс на русском языке.
6. Никаких TODO, заглушек и пустых обработчиков: всё, что видно на экране, работает.

# ИНТЕРФЕЙС
- Две полноценные темы оформления — светлая и тёмная; переключение заметной кнопкой в шапке (иконка солнце/луна); выбор сохраняется в localStorage и применяется при следующем запуске.
- Акценты: акцент светлой темы — #0ea5e9, акцент тёмной темы — #a3e635; обе темы контрастны и читаемы на проекторе.
- Крупный UI для интерактивной доски: базовый шрифт от 20px, кнопки и поля ввода не меньше 48px.
- Управление мышью и с клавиатуры: Tab — переход, Enter — проверить, Esc — закрыть подсказку; заметная подсветка фокуса.
- Адаптивность: телефоны 360–430px, планшеты 768–1024px, ноутбуки 1366×768, доска 1920×1080 — без горизонтальной прокрутки, обрезаний и перекрытий на всех размерах.
- На телефоне: одна колонка, кнопки ответа на всю ширину, базовый шрифт от 16px, липкая нижняя панель действий («Проверить» / «Дальше») с учётом safe-area; системная клавиатура не перекрывает активное поле (scrollIntoView), плитки и drag-цели не мельче 48px.
- Звук: короткие звуки верного/неверного ответа и финала; включены по умолчанию; один заметный переключатель сверху выключает весь звук.
- Навигация: в шапке слева — заметная кнопка «только значек» (иконка домика или стрелки «←»), оформленная как ссылка <a href="../index.html">; переход в той же вкладке, стиль — как у остальных кнопок. Продублируй эту кнопку на итоговом экране рядом с «Новый вариант».
- Адрес главной страницы должен работать и локально (file://), и на GitHub Pages: относительный адрес (например, index.html или ../index.html) оставляй относительным, абсолютный URL используй как есть; никаких заглушек «#», javascript:void и несуществующих путей.
