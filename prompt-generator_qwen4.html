    Как получить тренажёр, который заработает с первого раза

    1. 1
      Выберите режим заданий

      Фиксированный каталог — задания переносятся дословно, ничего не генерируется. Генеративный банк — модель придумывает задания по теме и образцам. Режимы взаимоисключающие: смешивание — главная причина, по которой модель «уходит» в генерацию вместо переноса.

    2. 2
      Вставьте тексты заданий

      Ссылка не работает без веб-доступа, а каталоги отдают страницы скриптами. Скопируйте задания со страницы в поле «Текст заданий» — желательно вместе с ответами из разборов: тогда эталоны берутся из источника и модель их не выдумывает.

    3. 3
      Уточните механику

      Свободное описание плюс схема данных: сколько шагов и лишних фрагментов, что считается промахом, когда проверять, фиксировать ли верные позиции, сколько попыток. Без этого модель решает по-своему — и по-разному в разных частях файла.

    4. 4
      Проверьте объём и разбивку

      Оценка справа показывает ожидаемый размер ответа. Если нужно больше одного продолжения — включите «Данные + движок»: сначала только массив TASKS (легко сверить глазами), затем движок, который его рендерит. На продолжениях модели чаще всего ломают код.

    5. 5
      Примите работу по чек-листу

      Обязательно сверьте 3 случайных задания со страницей источника дословно и пересчитайте эталоны там, где ответов в источнике не было.

    Три конфликта, которые ломали прошлые версии: «перенести дословно» вместе с «собери банк из 3–6 шаблонов»; «сложность треть/треть/треть» при фиксированном каталоге; «Новый вариант = свежая генерация» при переносе. Теперь режим каталога удаляет все генеративные требования, а линтер показывает такие сочетания как ошибки и умеет исправить их одной кнопкой.
    Данные отдельно от движка. В режиме «Данные + движок» промпт делится на две части: часть 1 просит только const TASKS = [...] по схеме, часть 2 — trainer.html, который рендерит готовый массив и не придумывает заданий. Так проверяемость выше, а продолжения не ломают движок.
    Если код оборвался: «продолжи ровно с места обрыва, без повторов». Массив данных continuing безопаснее, чем код: закрывающие скобки не «плывут».
    Сайт на GitHub Pages: репозиторий → index.html + файлы тренажёров → Settings → Pages → Deploy from a branch → main → / (root). В «Дополнительно» укажите index.html, для подпапки — ../index.html.

    Главная ошибка

    Просить «перенеси точно» и одновременно «сгенерируй банк». Модель выберет генерацию — она проще. Режим каталога убирает соблазн.

    Сначала данные

    Массив TASKS проверить глазами легко, код на 1500 строк — нет. Разделяйте запросы, если заданий больше 12–15.

    Ответы из источника

    Вставляйте задания вместе с ответами: самопроверка 35 вычислений у модели работает плохо, готовые эталоны снимают проблему.

    Одна механика — одна схема

    Сборка из частей + упорядочивание + DnD без схемы = три разных реализации в одном файле. Включите «Уточнить механику».

    Звук без файлов

    Только Web Audio (осциллятор + gain). Иначе модель втащит base64-WAV или ссылку на mp3 и сломает самодостаточность.

    Телефон и доска

    Ответы нажимаются пальцем, drag работает без мыши, есть альтернатива «нажал фрагмент → нажал слот».

    Список задач

    Статусы «не решено / верно / ошибка» и синхронизация с текущим заданием, а не просто номера.

    Подсказки поштучно

    «Своя подсказка к каждому заданию» — иначе получите две общие фразы на весь вариант.
